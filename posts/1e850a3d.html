第18章 UI 特效实现

在前两章中，我们分别从 CPU 侧的顶点扩展机制以及 GPU 侧的 Shader 渲染机制出发，建立了 UGUI 底层渲染体系的基础认知。本章将在此前内容的基础上进一步深入，进入 UI 渲染中最直观、同时也是项目中使用最频繁的一部分 —— UI 特效实现。

在现代 UI 系统中，界面早已不再只是静态的信息展示层。为了提升视觉层次与交互反馈，开发者通常会在 UI 中加入大量动态特效，例如渐变、流光、灰化、描边、发光、溶解以及毛玻璃等效果。

这些效果虽然表现形式各不相同，但从底层实现角度来看，本质上几乎都可以归纳为两类技术路径。

第一类是基于顶点扩展（Mesh Modify）的实现方式。

这类方案通常在 CPU 侧直接修改 UI 网格数据，例如修改顶点颜色、扩展顶点、复制顶点或调整顶点位置等。由于效果生成阶段发生在 Mesh 构建期间，因此通常不会增加额外的像素计算开销。这类方案的特点是性能稳定、实现简单，并且能够较好地兼容 UGUI 批处理机制，因此非常适合实现渐变、阴影、简单描边等轻量级效果。

第二类则是**基于 Shader **的像素计算方案。

这类方案会在 GPU 侧对 Fragment 进行实时计算，例如 UV 插值、颜色混合、多重采样、条件裁剪以及噪声计算等。相比 Mesh 修改方案，Shader 特效具备更强的表现能力，能够实现更加复杂的动态效果，例如流光、发光、溶解以及模糊等高级视觉表现。

不过，这类方案的性能消耗通常集中在 Fragment 阶段，并且会随着 UI Overdraw 增加而迅速上升。因此在移动平台中，Shader 类 UI 特效往往也是界面性能问题的主要来源之一。

需要注意的是，UGUI 特效与普通 Mesh Shader 存在明显差异。

由于 UGUI 建立在 CanvasRenderer 与 Canvas 批处理体系之上，因此所有 UI 特效都必须额外考虑 Mask、RectMask2D、动态图集、Stencil Buffer 以及 Canvas 合批等问题。很多在普通模型渲染中完全正常的 Shader，在 UGUI 中却可能出现遮罩失效、批处理中断或者裁剪异常等问题。

因此，本章不仅会介绍各种 UI 特效的实现方式，更会重点分析这些效果在 UGUI 渲染体系中的底层工作原理，以及它们对批处理、重建机制与渲染性能所带来的影响。

18.1 渐变效果

渐变（Gradient）是 UI 中最基础、也是使用最广泛的视觉效果之一，常用于按钮背景、标题文字、面板装饰等场景。相比纯色填充，渐变可以有效提升 UI 的层次感与精致度。

18.1.1 原理分析

渐变效果的核心可以概括为：在空间坐标（通常为 UV 或顶点）上，对颜色进行插值计算。

  1. 线性插值（Lerp）

渐变的本质是线性插值：C=(1−t)C1+tC2

其中：

  • C1：起始颜色

  • C2：结束颜色

  • t：插值因子（0~1）

  1. 插值因子来源

在 UI 中，常见的 t 来源有两种：

基于 UV

特点：

  • 完全在 GPU 计算

  • 不增加顶点数据

  • 适合动态渐变

基于顶点颜色

顶点颜色不同 → GPU自动插值

特点：

  • 在 CPU 设置顶点颜色

  • GPU 自动插值

  • 性能极高（无额外计算）

  1. 渐变方向控制

渐变不仅限于水平/垂直，还可以扩展为任意方向：

例如：

  • float2(1,0) → 水平渐变

  • float2(0,1) → 垂直渐变

  • float2(1,1) → 对角渐变

18.2 流光效果

流光（Shine）是 UI 中非常常见的一种视觉增强效果，常用于按钮、卡片、Banner 等区域，用于模拟“光线扫过表面”的高端质感。在 Unity UGUI 中，流光效果本质上是通过 UV 计算 + Shader 线性遮罩 + 时间驱动偏移 实现的。

18.4 描边效果

描边（Outline）是 UI 视觉强化中非常重要的一类效果，广泛应用于文字强调、按钮边框、高亮提示等场景。相比简单的颜色变化，描边可以在不改变主体颜色的情况下显著提升可读性和层次感。

在 UGUI 中，描边既可以通过 CPU 侧 Mesh 扩展（内置 Outline 组件） 实现，也可以通过 Shader 多重采样 实现。本节重点讲解更通用、可控性更强的 Shader 方案。

18.6 溶解效果

溶解（Dissolve）是一种在 UI 与游戏特效中广泛使用的视觉表现，常用于元素的“逐渐消失”或“生成出现”，例如技能解锁、卡片翻开、UI消散等场景。相比简单的透明度渐变，溶解具有更强的随机性和视觉冲击力。

本节将围绕溶解效果，从原理到完整 Shader 实现进行系统讲解。

18.7 毛玻璃效果

毛玻璃（Glass Blur）是一种在 UI 系统中广泛使用的视觉效果，常见于弹窗背景、系统面板、卡片容器等场景。其核心特征是：对背景内容进行模糊处理，同时保留半透明与颜色调制，从而形成类似“磨砂玻璃”的视觉效果。

相比普通模糊（Blur），毛玻璃更强调：

  • 背景采样（而非自身模糊）

  • 半透明叠加

  • 色彩调制（Tint）

  • 视觉增强（Vibrancy）

18.7.1 原理分析

毛玻璃效果的本质可以概括为：在屏幕空间中采样背景图像，并对其进行高斯模糊后，再与 UI 遮罩和颜色进行混合。

  1. 屏幕采样（GrabPass）

与普通 UI Shader 最大的区别在于：GrabPass { “_GrabTexture” }

作用：

  • 捕获当前屏幕已经渲染的内容

  • 作为后续模糊计算的数据来源

  1. 高斯模糊（Gaussian Blur）

为了获得自然的模糊效果，通常采用高斯分布权重：col += tex2D(_GrabTexture, uv + offset) * weight;

特点：

  • 中心权重大

  • 边缘权重小

  • 模糊更柔和自然

  1. 双 Pass 模糊（关键优化）

将二维模糊拆分为：

横向模糊（Horizontal）

↓

纵向模糊（Vertical）

优势：

  • 复杂度从 N² → 2N

  • 性能大幅提升

  1. UI Mask 控制

作用：

  • 控制毛玻璃显示区域

  • 支持 UGUI Image / Sprite 形状

  1. 色彩增强（Vibrancy）

作用：

  • 提升颜色饱和度

  • 模拟 iOS 风格玻璃质感

  1. 毛玻璃染色（Tint）

作用：

  • 给模糊结果添加整体色调

  • 常用于白色 / 黑色半透明 UI

  1. 整体流程总结

屏幕采样 → 高斯模糊（横向+纵向） → Mask裁剪 → 色彩增强 → Tint混合

本章小结

本章围绕 UGUI 中常见的 UI 特效实现展开，从渐变、流光到灰化、描边、发光、溶解以及毛玻璃等效果，系统分析了它们在 UGUI 渲染体系中的实现方式，并进一步讨论了这些效果背后的底层渲染逻辑。

虽然这些 UI 特效在视觉表现上存在明显差异，但从底层实现角度来看，它们本质上都建立在 UGUI 的 Mesh 生成机制与 Shader 渲染机制之上。

其中，一部分效果通过 CPU 侧的顶点扩展完成，例如渐变、阴影以及部分描边效果。这类方案通常直接修改 UI 顶点数据，包括顶点颜色、顶点位置以及额外顶点扩展等。由于效果生成阶段发生在 Mesh 构建期间，因此通常不会产生额外的 Fragment 计算开销，同时也更容易维持 UGUI 的批处理效率。

另一部分效果则更多依赖 GPU 侧的 Shader 计算，例如流光、发光、溶解以及模糊等动态效果。这类方案通常会在 Fragment 阶段进行 UV 插值、多重采样、颜色混合、阈值裁剪以及噪声计算，从而实现更加复杂的视觉表现。

从 Shader 逻辑角度来看，本章中的大部分 UI 特效又可以进一步归纳为几种基础渲染模型。

颜色变换类效果主要通过颜色插值与颜色重映射实现，例如渐变与灰化。

空间采样类效果则依赖邻域像素采样，通过对周围像素进行多方向偏移与累加，形成描边或发光等扩展视觉效果。

时间与 UV 驱动类效果通常基于 UV 坐标与时间变量构建动态变化路径，例如流光效果中的光带移动。

条件裁剪类效果则主要通过阈值判断控制像素显示与否，例如溶解效果中的噪声裁剪。

尽管具体实现方式不同，但这些效果最终都离不开几个核心能力：

  • 基于 UV 的空间定位与插值计算

  • 基于邻域像素的多重采样

  • 基于数学函数的颜色混合与阈值控制

理解这一点非常重要。

因为 UI 特效的本质并不是“特殊效果”的简单堆叠，而是对顶点数据、纹理采样以及数学插值过程的不同组合方式。

当开发者真正理解了这些底层规律之后，就能够将各种 UI 特效重新还原为“数据计算”与“采样控制”问题，而不再局限于固定 Shader 模板本身。

与此同时，在实际项目中，实现 UI 特效时还必须额外考虑 UGUI 特有的渲染限制，例如 Canvas 合批、Stencil Buffer、Mask、RectMask2D 以及 Overdraw 等问题。

很多视觉效果虽然能够正确显示，但却可能因为额外采样、透明叠加或者批处理中断而带来严重性能问题。尤其在移动平台中，Fragment 开销往往远高于普通开发阶段的预估，因此 UI 特效不仅是视觉问题，同时也是渲染优化中的重点问题之一。
